# Agent Content Pipeline

Agent Content Pipeline is a Windows-first, local-first open-source workflow for turning one approved article into:

- a personal-site publication;
- a WeChat Official Account draft;
- one 16:9 explainer video;
- confirmed publications to Xiaohongshu, Douyin, and Bilibili.

The product is controlled through a deterministic Python CLI. A project-local Skill teaches compatible agents how to create the content artifacts and when to request approval. The core never calls an LLM.

## Status

The local CLI, article compatibility path, video engine, Chrome/CDP driver, and first three social adapters are implemented. The offline suite is green; version 1.0 remains unreleased until separately approved live publications prove Xiaohongshu, Douyin, and Bilibili against their current creator pages.

## Development setup

```powershell
uv sync --dev
uv run pytest
uv run acp --help
uv run acp doctor --project-root .
```

Runtime requirements:

- Windows 10 or newer for the first supported release;
- Python 3.11 or 3.12;
- FFmpeg and FFprobe on `PATH`;
- locally installed Google Chrome;
- an internet connection for Pexels and Edge TTS when those adapters are selected.

## Local configuration

Create the single user-editable plaintext configuration file:

```powershell
uv run acp config init --project-root .
```

For the maintainer's existing article-publisher installation, migrate the proven VPS endpoint and bearer token without printing them:

```powershell
uv run acp config migrate-legacy-article `
  --project-root . `
  --legacy-push ..\.agents\skills\article-publisher\scripts\push.mjs
```

Edit `.local/secrets.toml` directly. Pexels is optional when local video materials are supplied. Edge TTS sends the narration text to Microsoft's online speech service; do not run it with private text unless that data transfer is acceptable.

## One Product workflow

Create a Product and add immutable article, cover, video-script, local-material, and social-copy revisions:

```powershell
uv run acp product create --title "标题" --slug article-slug --date 2026-08-10
uv run acp artifact add-article --product <product> --mdx article.mdx --body-html body.html --wechat-html index.html
uv run acp artifact add-cover --product <product> --cover cover.png
uv run acp artifact add-video-script --product <product> --script script.json
uv run acp artifact add-video-material --product <product> --material clip-1.mp4 --material clip-2.mp4
uv run acp artifact add-social-copy --product <product> --copy copy.json
```

Record approval of exact revisions. Publication approval keys are generated by dedicated commands so an Agent does not have to construct them:

```powershell
uv run acp approval record --product <product> --scope article --revision v001 --confirmed-by-user
uv run acp approval record --product <product> --scope cover --revision v001 --confirmed-by-user
uv run acp article approve-publication --product <product> --article-revision v001 --cover-revision v001 --confirmed-by-user
uv run acp article preview --project-root . --product <product> --article-revision v001 --cover-revision v001
uv run acp article publish --project-root . --product <product> --article-revision v001 --cover-revision v001

uv run acp approval record --product <product> --scope video-script --revision v001 --confirmed-by-user
uv run acp video render --project-root . --product <product> --script-revision v001 --material-revision v001
uv run acp approval record --product <product> --scope video --revision v001 --confirmed-by-user
```

Approve and submit each social platform independently:

```powershell
uv run acp social approve-publication --product <product> --platform bilibili --video-revision v001 --copy-revision v001 --confirmed-by-user
uv run acp social publish --project-root . --product <product> --platform bilibili --video-revision v001 --copy-revision v001
```

Use `xiaohongshu` or `douyin` for the other first-release targets. A visible local Chrome window opens automatically. If login is required, the command stops with `waiting_for_user`; complete login in that window and rerun the same command. The dedicated Profile remains under `.local/browser-profiles/<platform>/`.
